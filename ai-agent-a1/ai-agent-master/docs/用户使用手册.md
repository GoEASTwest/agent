# A1 多模态设备检修知识检索与作业系统用户使用手册

## 1. 手册说明

本文档面向系统使用者、评委和演示人员，说明如何启动系统、进入页面、使用主要功能、完成一条完整的设备检修业务流程。

系统主要访问地址：

```text
http://localhost:5173/love-app
```

后端接口地址：

```text
http://localhost:8123/api
```

## 2. 启动系统

### 2.1 启动后端

在 PowerShell 中执行：

```powershell
cd C:\Users\123\Desktop\Coding\agent\ai-agent-a1\ai-agent-master

$env:DASHSCOPE_API_KEY="你的DashScope API Key"
$env:DASHSCOPE_CHAT_MODEL="qwen3.7-plus"
$env:DASHSCOPE_COMPATIBLE_BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"

.\scripts\start-backend.ps1
```

如果需要启用 PostgreSQL 持久化，可在启动前设置：

```powershell
$env:DB_URL="jdbc:postgresql://localhost:5432/ai_agent"
$env:DB_USERNAME="postgres"
$env:DB_PASSWORD="postgres"
$env:APP_JDBC_PERSISTENCE_ENABLED="true"
$env:APP_PGVECTOR_ENABLED="false"
```

看到后端端口 `8123` 启动成功后，保持该窗口不要关闭。

### 2.2 启动前端

新开一个 PowerShell 窗口执行：

```powershell
cd C:\Users\123\Desktop\Coding\agent\ai-agent-a1\ai-agent-master
.\scripts\start-frontend.ps1
```

启动成功后打开浏览器访问：

```text
http://localhost:5173/love-app
```

系统主要页面包括：

## 4. 检修工作台使用说明

### 4.1 态势看板

进入 `/love-app` 后默认展示态势看板。

可查看：

- 设备总数
- 高风险设备数量
- 待处理作业
- 知识库数量
- 最近检修任务

如演示数据被多次操作打乱，可点击顶部的“重置演示数据”，恢复默认演示状态。

### 4.2 设备台账

在“设备台账”中可以查看和新建设备。

新建设备步骤：

1. 输入设备名称，例如“循环水泵三号”。
2. 选择设备类型，例如“泵”“电机”“风机”。
3. 输入位置，例如“动力站 C 区”。
4. 选择风险等级。
5. 输入传感器项，例如“温度、振动、电流”。
6. 点击新建设备。

启用 PostgreSQL 持久化后，新建设备会保存到数据库，项目重启后仍然存在。

### 4.3 故障案例

“故障案例”用于查看系统内置或专家审核通过的检修案例。

案例内容通常包括：

- 设备类型
- 故障名称
- 现象描述
- 图片特征
- 可能原因
- 处理方案

这些案例会参与知识检索和 AI 诊断参考。

### 4.4 多模态诊断

“多模态诊断”用于输入设备异常信息并生成诊断结果。

推荐填写：

1. 选择设备。
2. 选择设备类型。
3. 输入故障描述，例如“电机运行时温度升高，振动明显增大，伴随异响”。
4. 输入温度、振动、电流等参数。
5. 输入图片特征，例如“接线端子发黑、绝缘层破损、局部焦痕”。
6. 点击诊断。

系统会返回：

- 风险等级
- 证据链
- 可能原因
- 处理建议
- 相似案例
- 推荐作业单

诊断完成后，可以一键生成检修作业单。

### 4.5 视觉分析

“视觉分析”支持两种方式：

方式一：图片 URL 分析

1. 输入图片 URL。
2. 输入分析问题，例如“请判断可见缺陷、风险等级和检修建议”。
3. 点击分析。

方式二：上传图片分析

1. 选择本地图片。
2. 点击上传图片分析。

系统会返回：

- 可见缺陷
- 风险等级
- 可能原因
- 检修建议
- 推荐作业单方向

视觉分析结果可以同步到多模态诊断，并继续生成作业单。

### 4.6 检修作业单

“检修作业单”用于查看或新建检修任务。

作业单包含：

- 任务标题
- 所属设备
- 优先级
- 当前状态
- 标准作业步骤
- 备件工具
- 验收标准
- 下一步状态流转按钮

作业状态会根据当前阶段显示可执行的下一步操作。

### 4.7 作业流转

“作业流转”用于查看任务状态变化和操作记录。

支持的状态流程：

```text
待处理 -> 待派工 -> 处理中 -> 待验收 -> 专家复核 -> 已归档
专家复核 -> 驳回整改 -> 处理中
专家复核 -> 驳回整改 -> 待验收
```

每次状态变化都会记录：

- 任务编号
- 原状态
- 新状态
- 操作者角色
- 操作备注
- 操作时间

### 4.8 知识库

“知识库”用于检索已有资料，也可以提交新的现场经验。

知识检索支持：

- 本地 Markdown 检修资料
- 故障案例库
- 已审核通过的一线经验
- 可选 PgVector 向量检索

提交经验步骤：

1. 填写标题。
2. 填写设备类型。
3. 填写故障名称。
4. 填写症状、图片特征、原因和处理方案。
5. 提交知识贡献。

提交后记录会进入待审核状态。

### 4.9 知识审核

专家可以对一线提交的经验进行审核。

审核结果包括：

- 通过
- 驳回

审核通过后：

- 经验会进入故障案例库。
- 后续 AI 问答和知识检索可以引用该经验。
- 系统可生成 Markdown/PDF 归档文件。

### 4.10 报告中心

“报告中心”用于查看诊断历史、报告归档和专家修正记录。

可完成：

- 查看诊断报告
- 保存报告
- 查看归档记录
- 专家修正 AI 输出
- 查看修正历史

专家修正内容包括：

- 风险等级
- 证据
- 原因
- 处理措施
- 审核意见

### 4.11 AI 知识问答

“AI 知识问答”用于直接询问设备检修问题。

示例问题：

```text
循环水泵振动升高并伴随异响，应该如何排查？
```

系统会结合本地知识库、故障案例和已审核经验生成回答。回答内容支持 Markdown 渲染，不会直接显示 Markdown 源码。

## 5. 工具智能体使用说明

访问：

```text
http://localhost:5173/manus
```

工具智能体适合处理文档类任务，例如：

- 整理检修规程
- 生成 Markdown 文档
- 生成 PDF 报告
- 读取已保存文件
- 列出文件中心文件
- 下载公开维护资料

示例输入：

```text
请帮我整理一份循环水泵日常检修规程，包含安全要求、工具准备、操作步骤、验收标准和常见异常处理。
```

生成的 Markdown/PDF 文件可在文件中心查看。

## 6. 文件中心使用说明

访问：

```text
http://localhost:5173/files
```

文件中心可查看：

- 工具智能体生成的 Markdown 文件
- 生成的 PDF 文件
- 下载的外部资源

常用操作：

- 按文件类型筛选
- 预览 Markdown
- 下载文件
- 复制下载链接

## 7. 推荐演示流程

比赛答辩时建议按以下顺序演示：

1. 打开 `/love-app`，展示态势看板。
2. 进入设备台账，新建或选择一台设备。
3. 进入视觉分析，上传图片或输入图片 URL，得到缺陷分析结果。
4. 将视觉结果同步到多模态诊断。
5. 输入温度、振动、电流和故障描述，生成 AI 诊断结果。
6. 一键生成检修作业单。
7. 在检修作业单中执行状态流转。
8. 在作业流转页查看流转记录。
9. 在报告中心查看诊断报告，并演示专家修正。
10. 在知识库提交一条现场经验。
11. 专家审核通过后，再进行知识检索或 AI 问答，展示知识沉淀效果。
12. 打开文件中心，展示 Markdown/PDF 归档文件。

## 8. 常见问题

### 8.1 前端页面能打开，但接口报错

通常是后端没有启动，或前端代理没有连到 `8123` 端口。

处理：

```powershell
cd C:\Users\123\Desktop\Coding\agent\ai-agent-a1\ai-agent-master
.\scripts\start-backend.ps1
```

### 8.2 AI 没有回答

检查是否配置 DashScope API Key：

```powershell
echo $env:DASHSCOPE_API_KEY
```

如果为空，请重新设置：

```powershell
$env:DASHSCOPE_API_KEY="你的DashScope API Key"
```

### 8.3 新建数据重启后消失

说明当前处于内存演示模式。需要启用 PostgreSQL 持久化：

```powershell
$env:APP_JDBC_PERSISTENCE_ENABLED="true"
$env:DB_URL="jdbc:postgresql://localhost:5432/ai_agent"
$env:DB_USERNAME="postgres"
$env:DB_PASSWORD="postgres"
```

### 8.4 图片 URL 分析失败

可能是模型服务无法访问该图片 URL。可以改用“上传图片分析”。

### 8.5 PgVector 报错

如果 PostgreSQL 没有安装 pgvector 扩展，请保持：

```powershell
$env:APP_PGVECTOR_ENABLED="false"
```

系统仍会使用本地 Markdown、故障案例和已审核经验检索。

## 9. 注意事项

- 不要把真实 API Key 写入源码或提交包。
- 演示前建议点击“重置演示数据”，保持数据干净。
- 参赛最终环境必须在 LoongArch + 银河麒麟高级服务器操作系统上完成验证。
- 如果使用可执行 jar 和前端 dist 部署，前端静态服务需要把 `/api` 反向代理到后端 `http://localhost:8123/api`。
