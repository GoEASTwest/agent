# A1 多模态设备检修知识检索与作业系统方案设计说明书

## 1. 文档目的

本文档说明系统总体方案、技术架构、模块设计、数据设计、接口设计、部署方案和安全设计，作为参赛提交材料中的方案设计文档。

## 2. 总体方案

系统采用 B/S 架构，由 Vue 3 前端、Spring Boot 后端、DashScope/Qwen 大模型服务、PostgreSQL 业务数据库和可选 PgVector 向量知识库组成。

核心业务流程如下：

```text
设备台账
-> 文本/参数/图片输入
-> 知识库与案例召回
-> AI 风险诊断
-> 自动生成作业单
-> 作业状态流转
-> 报告归档
-> 一线经验提交
-> 专家审核
-> 知识沉淀与再次检索
```

系统默认保留内存演示兜底，便于比赛现场稳定启动；启用 `APP_JDBC_PERSISTENCE_ENABLED=true` 后，核心业务数据写入 PostgreSQL；启用 `APP_PGVECTOR_ENABLED=true` 后，知识库使用 PgVector 进行真实向量检索。

| 层级 | 技术/组件 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3、Vite、Axios、Vue Router | PC Web 可视化界面 |
| 后端 | Java 21、Spring Boot、Spring AI | REST API、AI 调用、业务编排 |

## 7. 作业状态设计

作业流转状态如下：

```text
待处理 -> 待派工 -> 处理中 -> 待验收 -> 专家复核 -> 已归档
专家复核 -> 驳回整改 -> 处理中
专家复核 -> 驳回整改 -> 待验收
```

前端只展示当前状态允许执行的下一步按钮；后端通过状态校验避免非法流转。

## 8. 知识库设计

系统采用“两级知识库”方案：

- 稳定演示路线：本地 Markdown + 故障案例 + 已审核经验统一检索。
- 增强路线：开启 PgVector 后，将本地 Markdown 文档切分为 chunks 写入向量库，用于语义相似度召回。

AI 回答优先使用可检索知识来源，并在页面展示命中来源、片段和匹配分，便于答辩时说明可追溯性。

## 10. 安全设计

- API Key 不写入源码，使用 `.env` 或系统环境变量注入。
- `.env`、运行日志、临时生成文件不作为源码提交内容。
- 工具智能体未开放任意终端命令执行，避免演示环境安全风险。
- 文件下载接口限制在系统生成文件目录内，避免任意路径读取。
