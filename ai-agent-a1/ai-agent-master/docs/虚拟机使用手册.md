# A1 多模态设备检修知识检索与作业系统虚拟机使用手册

## 1. 手册目的

本文档面向比赛远程虚拟机使用场景，说明如何在 LoongArch 架构 + 银河麒麟高级服务器操作系统中获取项目、安装依赖、配置环境变量、启动系统、验证功能和排查常见问题。

本手册适合答辩前现场操作使用；更偏部署细节的说明见：

```text
docs/银河麒麟LoongArch部署说明.md
```

## 2. 虚拟机登录后先检查环境

登录虚拟机后先执行：

```bash
uname -m
cat /etc/os-release
```

期望结果：

```text
loongarch64
银河麒麟 / Kylin V10 或 V11
```

如果 `uname -m` 显示 `x86_64`，说明不是赛题要求的最终运行环境。

## 3. 安装基础工具

优先使用系统软件源安装，避免下载 x86 安装包。

如果系统使用 `dnf`：

```bash
sudo dnf update -y
sudo dnf install -y git unzip curl fontconfig
```

如果系统使用 `apt`：

```bash
sudo apt update
sudo apt install -y git unzip curl fontconfig
```

## 4. 安装并检查 Java

项目后端需要 Java 21。

检查：

```bash
java -version
javac -version
```

如果没有 Java 21，可先尝试：

```bash
sudo dnf install -y java-21-openjdk java-21-openjdk-devel
```

如果软件源没有 Java 21，需要使用大赛平台或龙芯生态提供的 LoongArch64 JDK 包。不要使用 Windows 或 x86_64 JDK。

## 5. 安装并检查 Node.js

项目本地前端演示需要 Node.js/npm。

检查：

```bash
node -v
npm -v
```

推荐 Node.js 18 及以上。如果没有，可尝试：

```bash
sudo dnf install -y nodejs npm
```

## 6. 获取项目代码

### 6.1 方式一：从 GitHub 拉取

如果虚拟机能访问 GitHub：

```bash
cd ~/桌面
git clone -b Li https://github.com/GoEASTwest/agent.git
cd agent
```

如果之前已经 clone 过：

```bash
cd ~/桌面/agent
git checkout Li
git pull origin Li
```

### 6.2 方式二：上传提交压缩包

如果 GitHub 网络不稳定，可将本地提交包上传到虚拟机并解压：

```bash
unzip A1-设备检修知识检索与作业系统-Li-*.zip
cd A1-设备检修知识检索与作业系统-Li-*/source-code
```

后续命令中的项目根目录对应：

```text
ai-agent-a1/ai-agent-master
```

## 7. 配置环境变量

进入主项目：

```bash
cd ~/桌面/agent/ai-agent-a1/ai-agent-master
```

如果路径不同，请按实际解压路径进入 `ai-agent-master`。

复制环境变量模板：

```bash
cp .env.example .env
vi .env
```

首次运行建议配置为稳定演示模式：

```text
DASHSCOPE_API_KEY=你的DashScope密钥
DASHSCOPE_CHAT_MODEL=qwen3.7-plus
DASHSCOPE_COMPATIBLE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1

APP_JDBC_PERSISTENCE_ENABLED=false
APP_PGVECTOR_ENABLED=false
```

说明：

- `APP_JDBC_PERSISTENCE_ENABLED=false` 时使用内存演示数据，最容易先跑通。
- 后端和前端都正常后，再开启 PostgreSQL 持久化。

## 8. 构建后端

```bash
cd ~/桌面/agent/ai-agent-a1/ai-agent-master
chmod +x mvnw
./mvnw -DskipTests --no-transfer-progress package
```

构建成功后应生成：

```text
target/ai-agent-0.0.1-SNAPSHOT.jar
```

如果第一次构建很慢，通常是 Maven 正在下载依赖。可配置 Maven 镜像：

```bash
mkdir -p ~/.m2
cat > ~/.m2/settings.xml <<'EOF'
<settings>
  <mirrors>
    <mirror>
      <id>aliyunmaven</id>
      <mirrorOf>*</mirrorOf>
      <name>Aliyun Maven</name>
      <url>https://maven.aliyun.com/repository/public</url>
    </mirror>
  </mirrors>
</settings>
EOF
```

然后重新执行打包命令。

## 9. 启动后端

```bash
cd ~/桌面/agent/ai-agent-a1/ai-agent-master
set -a
source .env
set +a
java -jar target/ai-agent-0.0.1-SNAPSHOT.jar
```

后端默认端口：

```text
8123
```

另开终端检查：

```bash
curl http://127.0.0.1:8123/api/health
curl http://127.0.0.1:8123/api/maintenance/devices
```

能返回内容说明后端启动成功。

## 10. 启动前端

另开一个终端：

```bash
cd ~/桌面/agent/ai-agent-a1/ai-agent-master/ai-agent-frontend
npm install
npm run dev -- --host 0.0.0.0 --port 5173
```

访问：

```text
http://虚拟机IP:5173/love-app
```

如果在虚拟机桌面浏览器中访问：

```text
http://127.0.0.1:5173/love-app
```

## 11. 开启 PostgreSQL 持久化

系统先跑通后，再开启数据库持久化。

### 11.1 启动 PostgreSQL

检查状态：

```bash
cd /tmp
systemctl status postgresql --no-pager
```

如果显示 `inactive (dead)`，先初始化并启动：

```bash
sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql
systemctl status postgresql --no-pager
```

如果系统提示 `postgresql-setup` 用法不同，可试：

```bash
sudo postgresql-setup initdb
```

### 11.2 创建数据库

```bash
cd /tmp
sudo -u postgres psql
```

进入 psql 后执行：

```sql
create database ai_agent;
alter user postgres with password 'postgres';
\q
```

如果提示数据库已存在，只执行设置密码即可：

```sql
alter user postgres with password 'postgres';
\q
```

### 11.3 修改 `.env`

```bash
cd ~/桌面/agent/ai-agent-a1/ai-agent-master
vi .env
```

修改为：

```text
DB_URL=jdbc:postgresql://localhost:5432/ai_agent
DB_USERNAME=postgres
DB_PASSWORD=postgres
APP_JDBC_PERSISTENCE_ENABLED=true
APP_PGVECTOR_ENABLED=false
```

重启后端后，系统会自动执行建表和种子数据初始化。

## 12. 暂不建议开启 PgVector

比赛演示优先稳定，建议保持：

```text
APP_PGVECTOR_ENABLED=false
```

只有确认虚拟机已安装 pgvector 扩展后，再考虑开启：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

## 13. 虚拟机验收流程

前后端启动后，按以下顺序检查：

1. 打开 `/love-app`，确认检修工作台能显示。
2. 点击“重置演示数据”，恢复初始数据。
3. 进入设备台账，新建设备。
4. 刷新页面，确认数据仍存在；如果开启 PostgreSQL，重启后端后再次确认。
5. 进入视觉分析，输入图片 URL 或上传图片。
6. 将视觉分析结果同步到多模态诊断。
7. 生成 AI 诊断结果。
8. 一键生成检修作业单。
9. 演示状态流转：待派工、处理中、待验收、专家复核、已归档。
10. 进入知识库，提交经验并审核通过。
11. 进入 AI 知识问答，提问“摩托车发动机无法启动应该如何排查？”。
12. 进入报告中心和文件中心，查看归档文件。

## 15. 常见问题

### 15.1 `sudo -u postgres psql` 提示 Permission denied

如果出现：

```text
could not change directory ... Permission denied
```

先执行：

```bash
cd /tmp
sudo -u postgres psql
```

### 15.2 psql 连接 socket 失败

如果出现：

```text
No such file or directory
```

通常是 PostgreSQL 服务没启动。

处理：

```bash
sudo systemctl enable --now postgresql
systemctl status postgresql --no-pager
```

### 15.3 Maven 打包很久

第一次构建会下载依赖，可能很慢。可检查：

```bash
du -sh ~/.m2/repository
```

如果目录大小在增长，说明仍在下载依赖。

### 15.4 前端能打开但接口失败

检查后端是否启动：

```bash
curl http://127.0.0.1:8123/api/health
```

检查前端启动命令是否包含：

```bash
--host 0.0.0.0 --port 5173
```

### 15.5 AI 不回答

检查 `.env`：

```bash
grep DASHSCOPE .env
```

确认 `DASHSCOPE_API_KEY` 已填写，并且虚拟机能访问外网。

### 15.6 新增数据重启后消失

说明当前仍是内存模式。需要开启：

```text
APP_JDBC_PERSISTENCE_ENABLED=true
```

并确认 PostgreSQL 正常运行。
