# A1 多模态设备检修知识检索与作业系统需求分析说明书

## 1. 文档目的

本文档用于说明本系统的建设背景、用户角色、业务目标、功能需求、非功能需求和验收依据，作为参赛提交材料中的需求分析文档。

## 2. 项目背景

工业、能源、制造等场景中，生产设备数量多、结构复杂、检修知识来源分散。设备说明书、历史维修记录、现场经验和专家判断往往散落在不同文件或人员经验中，导致一线检修人员检索效率低、作业流程不统一、新人上手慢，严重时会扩大停机损失。

本系统面向设备检修场景，结合大模型问答、知识检索、图片分析、作业单流转和知识沉淀能力，建设一个可在 PC Web 端使用的设备检修知识检索与作业辅助系统。

## 3. 建设目标

- 支持云端大模型服务，预留本地模型兼容配置能力。
- 提供 B/S 架构 Web 可视化界面，便于检修人员、专家和管理员操作。
- 支持文本、设备型号、运行参数、故障图片等多类型输入。
- 支持检修知识检索、故障诊断、相似案例匹配和标准化作业指引。
- 支持检修任务从生成、派工、执行、验收、复核到归档的闭环流转。
- 支持一线经验提交、专家审核、知识入库和 AI 输出修正记录。
- 支持 PostgreSQL 持久化和可选 PgVector 向量检索，便于后续扩展真实知识库。

## 4. 用户角色

| 角色 | 主要职责 | 系统能力 |
| --- | --- | --- |
| 巡检人员 | 发现设备异常，提交现象、参数、图片等信息 | 设备台账、故障诊断、图片分析、经验提交 |
| 检修人员 | 根据作业单执行检修任务 | 作业步骤查看、状态流转、报告归档 |
| 专家人员 | 审核知识、复核作业、修正 AI 输出 | 知识审核、专家复核、报告修正 |
| 管理人员 | 关注设备风险、任务进度和知识沉淀 | 态势看板、任务列表、报告中心、文件中心 |

## 5. 功能需求

### 5.1 大模型服务与 Web 界面

- 系统应支持云端大模型 API 调用，当前通过 DashScope/Qwen OpenAI 兼容模式实现。
- 系统应提供 PC Web 可视化界面，覆盖首页工具智能体、检修工作台和文件中心。
- 系统应支持流式问答，提升用户等待过程中的可感知性。

### 5.2 多模态知识检索

- 系统应支持文本问题输入，结合本地 Markdown 检修资料、故障案例和已审核经验进行检索。
- 系统应支持设备编号、设备类型、位置、传感器项等结构化信息输入。
- 系统应支持故障图片 URL 分析和本地图片上传分析。
- 系统应支持可选 PgVector 向量检索，启用后将本地检修文档切分入库并进行相似度召回。
- 系统应在 AI 回答中展示可追溯的知识来源或相似案例信息。

### 5.3 标准化作业指引

- 系统应根据诊断结果自动生成检修作业单。
- 作业单应包含设备编号、任务标题、优先级、状态、操作步骤、备件工具和验收标准。
- 系统应提供停机、断电、泄压、挂牌上锁、PPE 等安全合规提醒。
- 系统应支持真实检修流程中的状态流转，包括待派工、处理中、待验收、专家复核、驳回整改、已归档。
- 系统应记录每次状态流转的操作者角色、前后状态、备注和时间。

### 5.4 知识沉淀与更新

- 系统应支持一线人员提交故障案例、经验总结、图片特征、原因分析和处理方案。
- 系统应支持专家审核知识贡献，审核通过后进入案例库并可被后续检索引用。
- 系统应支持将审核通过的经验生成 Markdown/PDF 文件并进入文件中心。
- 系统应支持专家手动修正 AI 输出，包括风险等级、证据、原因、措施和审核意见。
- 系统应保存 AI 修正记录，便于后续复盘和模型适配优化。

### 5.5 数据持久化

- 系统应支持默认内存演示模式，保证数据库未启动时仍可展示核心流程。
- 系统应支持 PostgreSQL 持久化模式，保存设备、案例、任务、流转、报告、知识审核和修正记录。
- 系统应支持一键重置演示数据，便于答辩现场恢复干净演示状态。

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 易用性 | 页面结构清晰，操作入口明确，适合 PC Web 演示和现场操作 |
| 稳定性 | 数据库、PgVector、搜索等能力均采用开关配置，避免单点依赖导致系统无法启动 |
| 可维护性 | 前后端分层清晰，业务模型、控制器、服务和持久化模块相对独立 |
| 可扩展性 | 支持后续接入本地大模型、LoongArch 部署、PgVector、图片向量检索和真实权限体系 |
| 安全性 | API Key 不写入源码，通过 `.env` 或环境变量配置；生成文件默认不提交到 Git |
| 兼容性 | 采用 Java 21、Spring Boot、Vue 3、Vite，可迁移到银河麒麟 LoongArch 环境验证 |

## 7. 约束条件

- 最终比赛运行环境要求为 LoongArch 架构和银河麒麟高级服务器操作系统 V11/V10。
- 云端大模型调用依赖 DashScope API Key 和外网访问能力。
- PgVector 向量检索依赖 PostgreSQL 安装 pgvector 扩展；未安装时可关闭该能力。
- 图片 URL 分析依赖模型服务能够访问图片地址；系统同时提供上传图片本地分析兜底。

## 8. 验收标准

- 前后端能够正常启动，访问 `/love-app` 完成主要演示流程。
- AI 问答、知识检索、设备诊断、视觉分析、作业单生成和报告归档可用。
- 新建设备、任务、知识贡献、报告修正在启用 PostgreSQL 后可持久保存。
- 知识审核通过后能够进入案例库或文件中心。
- 本地执行 `scripts/check-local.ps1` 后，后端打包和前端构建能够通过。
- 在比赛虚拟机上完成 LoongArch/银河麒麟部署验证后，满足赛题硬性运行环境要求。
