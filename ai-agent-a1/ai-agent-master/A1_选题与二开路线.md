# A1 选题与二开路线

## 结论

建议选择 **A1-基于多模态大模型技术的设备检修知识检索与作业系统**。

这个题目最适合快速做出可演示作品：已有 Spring AI + Vue + RAG + Agent 源码可以复用，需求边界清晰，评委容易理解“现场输入 -> 知识检索 -> 诊断建议 -> 作业单 -> 报告”的闭环。

## 为什么不优先选其他题

| 题目 | 风险 |
| --- | --- |
| A2 麒麟安全运维 Agent | 需要麒麟环境、安全运维场景和系统权限，调试成本高 |
| A3 个性化学习多智能体 | 容易做成普通教育聊天机器人，同质化严重 |
| A4 云边端仓储仿真 | 依赖指定平台和仿真链路，工程量偏大 |
| A5 景区数字人 | 数字人效果吃模型、语音、形象和实时渲染，成本高且竞品多 |
| A6 金蝶 AI 苍穹 | 强依赖厂商生态和业务理解 |
| A7 AR + 机器狗消防 | 硬件、AR、实时控制门槛高 |
| A8 无人机控制 | 控制算法与硬件/仿真调参要求高 |
| A9 OpenHarmony 家居控制 | 需要 OpenHarmony 设备或模拟环境，创新空间相对有限 |

## 已完成的第二轮工程化改造

本轮目标是把项目从“AI 问答 Demo”扩成“设备检修业务系统原型”，增加工程量和可答辩功能面。

### 后端新增模块

新增 `com.hp.aiagent.maintenance` 业务域：

- `model/DeviceAsset.java`：设备台账模型，包含设备编号、类型、位置、状态、风险等级、传感器列表、最近巡检时间。
- `model/FaultCase.java`：故障案例模型，包含设备类型、故障名称、症状、图片特征、原因、处理方案、严重度。
- `model/InspectionRequest.java`：多模态诊断输入，包含文本描述、温度、振动、电流、图片特征。
- `model/DiagnosisResult.java`：诊断输出，包含风险等级、评分、证据链、可能原因、建议动作、相似案例、自动生成作业单。
- `model/MaintenanceTask.java`：检修作业单模型，包含步骤、备件工具、验收标准、优先级和状态。
- `model/DashboardSummary.java`：态势看板聚合模型。
- `service/MaintenanceService.java`：内存演示数据、风险评分、相似案例匹配、作业单生成。
- `controller/MaintenanceController.java`：REST API。

### 新增接口

| 接口 | 方法 | 作用 |
| --- | --- | --- |
| `/api/maintenance/dashboard` | GET | 获取设备数、异常数、作业单数、风险分布 |
| `/api/maintenance/devices` | GET | 获取设备台账 |
| `/api/maintenance/cases` | GET | 获取故障案例知识库 |

### 前端新增功能面

`LoveApp.vue` 已从单一聊天页升级为多模块检修中台：

- 态势看板：设备数、异常设备、待处理作业、知识案例、风险分布、最近作业。
- 设备台账：展示设备类型、位置、状态、风险等级和传感器。
- 案例知识库：展示故障症状、图片特征、原因和处理方案。
- 多模态诊断：输入设备、温度、振动、电流、现场描述、图片可见特征，输出风险评分、证据链、可能原因和作业建议。
- 检修作业单：展示自动生成的作业步骤、备件工具、验收标准。
- AI 知识问答：保留原有 Spring AI + SSE 能力。
- 演示兜底：后端未启动时自动使用本地模拟数据，保证答辩演示不中断。
- 报告导出：诊断结果可导出为 Markdown 报告。

## 冲奖改造路线

### 第一阶段：可运行演示

- 完成前后端启动脚本。
- 准备 20 到 50 条设备检修知识文档，覆盖风机、泵、轴承、电机。
- 准备 10 个现场案例：温升、振动、异响、漏油、烧蚀、裂纹、磨损。
- 增加报告导出格式：Markdown、PDF、Word 三种。

### 第二阶段：多模态能力

- 从 `image-backend` 抽取图片上传、分类标签、审核和相似检索。
- 增加故障图片分析接口：图片 + 文本问题 -> 可见故障特征 -> 相似案例 -> 检修建议。
- 可选模型：Qwen-VL、GLM-4V、InternVL、本地 CLIP 向量检索。

### 第三阶段：真实数据持久化

- 设备台账、案例库、作业单迁移到 MySQL/PostgreSQL。
- 知识文档向量化进入 PgVector。
- 图片元数据进入对象存储或本地 MinIO。
- 增加登录、角色权限：巡检员、检修员、专家、管理员。

### 第四阶段：作业系统闭环

- 增加检修作业单实体：设备、位置、异常、风险、步骤、备件、验收标准、负责人。
- 增加状态流转：待诊断、待检修、检修中、待验收、已归档。
- 增加报告模板：诊断报告、作业指导书、复盘报告。

### 第五阶段：答辩亮点

- 知识库回答带依据，不做纯大模型幻觉问答。
- 图片、文本、参数三类输入合一，体现“多模态”。
- 从“问答”升级为“检修作业闭环”，贴合赛题的作业系统。
- 支持案例沉淀和复盘，让系统越用越有行业知识。

## 建议演示脚本

1. 上传或选择一张“轴承烧蚀/漏油/锈蚀”故障图片。
2. 输入现场描述：温度、振动、噪声、持续时间。
3. 系统输出风险等级、可能原因和补充检查项。
4. 点击生成检修作业单，展示安全隔离、检查步骤、备件、验收标准。
5. 导出诊断报告，作为闭环结果。
